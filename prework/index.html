Prerequisites¶

Complete these steps on your lab machine before the first module. Everything runs inside the Linux environment (WSL) on the machine. The app uses SQLite, an embedded database file, so there is no server or container to set up.

Own machine?

These instructions are for the provisioned lab machines. If you're on your own machine, ask a facilitator.

1. Open the Linux terminal¶

Open Fedora Linux from the Start menu (or wsl.exe on the desktop). Every command below runs in this terminal, not in PowerShell or Command Prompt.

2. Install make¶

The SQLite driver compiles a small native component on first install, and the image ships without make:

sudo yum install -y make

3. Confirm the toolchain¶

node --version && npm --version && git --version

You should see Node v22.x or newer and version numbers for npm and git. If anything is missing, flag a facilitator before going further.

4. Clone and set up¶

Switch to your home directory:

cd ~

Then clone the repo and run setup:

git clone https://github.com/hbattu73/finch-financial.git
cd finch-financial
npm run setup

npm run setup installs dependencies, creates api/.env with working defaults, creates the SQLite database, and seeds it. It takes about a minute. Ignore the npm warn deprecated lines and the vulnerabilities summary at the end. Neither affects the workshop.

5. Start the app¶

npm run dev

This starts the API (port 3000) and the web app (port 5173) in one terminal. Open http://localhost:5173 in the Windows browser. WSL forwards the port automatically. Log in with any seeded user. All users share the password Password123!.

You should see a list of customer accounts with status badges, filters by status and name, and an account detail page with transactions, memos and an audit log. If you can browse accounts, the app is ready. Stop it with Ctrl+C.

6. Connect Bob IDE to the Linux environment¶

Bob IDE needs an extension to see the Linux filesystem.

  1. Open IBM Bob from the Start menu.
  2. Open the Extensions view (Ctrl+Shift+X), search for Open Remote - WSL (publisher: jeanp413), and install it.
  3. Press Ctrl+Shift+P, type WSL, and choose Connect to WSL. A new Bob window opens inside the Linux environment. Its title bar shows the distro name.
  4. In that window, File → Open Folder and open /home/<your-user>/finch-financial.
  5. If Bob asks whether you trust the authors of the folder, click Yes, I trust the authors.

You should see AGENTS.md, product-requests.md and PROMPTS.md in the file tree, and the Bob icon in the activity bar on the left. If the icon is missing or the panel is blank, see Troubleshooting below.

Open the Bob panel and check Settings → Skills: interview should be listed with scope Workspace. You're ready.

Next Steps¶

Proceed to the Presentation.

Testing¶

Both test suites are standalone: no running server and no database setup. Your development data is never touched.

npm test              # everything
npm test -w api       # one workspace
npm test -w web

Troubleshooting¶

npm run setup fails building better-sqlite3

The error block mentions node-gyp rebuild. make isn't installed. Run sudo yum install -y make, then npm run setup again.

localhost:5173 doesn't load in the Windows browser

Confirm npm run dev is still running in the Linux terminal. If it is and the page still won't load, run hostname -I in the terminal and use that address in place of localhost.

Port 3000 or 5173 is already in use

Another process is holding the port, usually a previous npm run dev. Find and stop it: 

lsof -ti:3000 | xargs kill
lsof -ti:5173 | xargs kill

Bob can't see the repo files

Bob has to open the folder from inside the Linux environment. If you opened it via a Windows path (\\wsl$\... or C:\...), close that window and repeat step 6.

Bob icon missing or chat panel blank

First, look at the bottom-left of the status bar for Restricted Mode. If it's there, click it and choose Trust, then reload the window.

If that doesn't fix it, run the repair script:

  1. Close Bob IDE completely.
  2. Expand the block below, copy the whole script, and save it to your Windows Desktop as fix-bob-ide.ps1. In Notepad: paste, File → Save As, set Save as type to All Files, name it fix-bob-ide.ps1.
  3. Open PowerShell on the Windows side (not the Linux terminal) and run: 
    powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\fix-bob-ide.ps1"
  4. It prints what it changed. Relaunch Bob from the Start menu and repeat step 6 above.

Don't paste the script straight into the PowerShell window. It has to run from a file. Flag a facilitator if you'd rather have someone run it with you.

fix-bob-ide.ps1 (click to expand) 
# fix-bob-ide.ps1
# Fixes IBM Bob IDE showing a blank panel when launched from C:\Windows\System32.
#
# Root cause: the IDE inherits System32 as its working directory from the Start Menu
# shortcut (no working directory set). VS Code treats System32 as an untrusted
# workspace and disables the bob-code extension, leaving a blank panel.
#
# This script applies three independent fixes; each is idempotent and reports its own result:
#   1. Disables workspace trust in the IDE's user settings.json (no dependencies)
#   2. Adds C:\Windows\System32 to the trusted-folders database (requires Python)
#   3. Sets C:\Users\<username> as the Start Menu shortcut's working directory
#
# Run this script WHILE THE IBM BOB IDE IS CLOSED.

param(
    [switch]$SkipSettings,
    [switch]$SkipTrustDb,
    [switch]$SkipShortcut
)

$ErrorActionPreference = "Stop"
$results = @()

# --- Verify IBM Bob IDE is not running (match by path, not by guessed process name) ---
$running = Get-Process | Where-Object { $_.Path -and $_.Path -like "*IBM Bob*" }
if ($running) {
    Write-Error "IBM Bob IDE appears to be running ($($running[0].ProcessName)). Close it and run this script again."
    exit 1
}

$userDir = "$env:APPDATA\IBM Bob\User"
if (-not (Test-Path $userDir)) {
    Write-Error "Could not find IBM Bob user data at: $userDir. Has the IDE been launched at least once?"
    exit 1
}

# --- Fix 1: disable workspace trust in settings.json ---
if (-not $SkipSettings) {
    Write-Host "Fix 1: disabling workspace trust in settings.json..." -ForegroundColor Cyan
    try {
        $settingsPath = Join-Path $userDir "settings.json"
        $settings = @{}
        if (Test-Path $settingsPath) {
            $raw = Get-Content $settingsPath -Raw
            if ($raw.Trim()) {
                $obj = $raw | ConvertFrom-Json
                $obj.PSObject.Properties | ForEach-Object { $settings[$_.Name] = $_.Value }
            }
        }
        if ($settings["security.workspace.trust.enabled"] -eq $false) {
            $results += "Fix 1: already applied."
        } else {
            $settings["security.workspace.trust.enabled"] = $false
            $settings | ConvertTo-Json -Depth 10 | Set-Content -Path $settingsPath -Encoding UTF8
            $results += "Fix 1: workspace trust disabled."
        }
    } catch {
        $results += "Fix 1: FAILED - $($_.Exception.Message)"
    }
}

# --- Fix 2: trust C:\Windows\System32 in the workspace trust database ---
if (-not $SkipTrustDb) {
    Write-Host "Fix 2: patching workspace trust database..." -ForegroundColor Cyan
    $db = Join-Path $userDir "globalStorage\state.vscdb"
    $py = Get-Command python -ErrorAction SilentlyContinue
    $pyOk = $false
    if ($py) {
        # Rule out the Microsoft Store stub, which exists but does nothing useful
        $ver = & python --version 2>&1
        if ($LASTEXITCODE -eq 0 -and "$ver" -match "^Python 3") { $pyOk = $true }
    }

    if (-not (Test-Path $db)) {
        $results += "Fix 2: SKIPPED - state.vscdb not found at $db."
    } elseif (-not $pyOk) {
        $results += "Fix 2: SKIPPED - Python 3 not available on Windows (Fix 1 covers the same symptom)."
    } else {
        $pyScript = [System.IO.Path]::GetTempFileName() + ".py"
        $pyLines = @(
            "import sqlite3, json, sys",
            "db  = sys.argv[1]",
            "key = 'content.trust.model.key'",
            "conn = sqlite3.connect(db)",
            "cur  = conn.cursor()",
            "cur.execute('SELECT value FROM ItemTable WHERE key=?', (key,))",
            "row = cur.fetchone()",
            "data = json.loads(row[0]) if row else {'uriTrustInfo': []}",
            "entries = data.get('uriTrustInfo', [])",
            "already = any(e.get('uri', {}).get('path', '').lower() == '/c:/windows/system32' for e in entries)",
            "if already:",
            "    print('already trusted')",
            "else:",
            "    entries.append({'uri': {'`$mid': 1, 'path': '/c:/Windows/System32', 'scheme': 'file'}, 'trusted': True})",
            "    data['uriTrustInfo'] = entries",
            "    val = json.dumps(data)",
            "    if row:",
            "        cur.execute('UPDATE ItemTable SET value=? WHERE key=?', (val, key))",
            "    else:",
            "        cur.execute('INSERT INTO ItemTable (key, value) VALUES (?, ?)', (key, val))",
            "    conn.commit()",
            "    print('trusted')",
            "conn.close()"
        )
        Set-Content -Path $pyScript -Encoding UTF8 -Value ($pyLines -join "`n")
        $out = & python $pyScript $db 2>&1
        $code = $LASTEXITCODE
        Remove-Item $pyScript -Force -ErrorAction SilentlyContinue
        if ($code -eq 0) {
            $results += "Fix 2: $out."
        } else {
            $results += "Fix 2: FAILED - $out"
        }
    }
}

# --- Fix 3: set working directory on the Start Menu / Desktop shortcut ---
if (-not $SkipShortcut) {
    Write-Host "Fix 3: fixing shortcut working directory..." -ForegroundColor Cyan
    $shortcutPaths = @(
        "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\IBM Bob.lnk",
        "$env:PROGRAMDATA\Microsoft\Windows\Start Menu\Programs\IBM Bob.lnk",
        "$env:USERPROFILE\Desktop\IBM Bob.lnk"
    )
    $found = $false
    foreach ($path in $shortcutPaths) {
        if (-not (Test-Path $path)) { continue }
        $found = $true
        try {
            $shell    = New-Object -ComObject WScript.Shell
            $shortcut = $shell.CreateShortcut($path)
            if ($shortcut.WorkingDirectory -eq $env:USERPROFILE) {
                $results += "Fix 3: $path already correct."
            } else {
                $shortcut.WorkingDirectory = $env:USERPROFILE
                $shortcut.Save()
                $results += "Fix 3: $path updated."
            }
        } catch {
            $results += "Fix 3: could not update $path - $($_.Exception.Message) (likely needs admin; Fix 1 still applies)."
        }
    }
    if (-not $found) {
        $results += "Fix 3: no shortcut found at the standard locations."
    }
}

Write-Host ""
Write-Host "Results:" -ForegroundColor Green
$results | ForEach-Object { Write-Host "  $_" }
Write-Host ""
Write-Host "Launch IBM Bob from the Start Menu. If the panel is still blank, check the status bar for 'Restricted Mode' and click Trust." -ForegroundColor Green
git status shows package-lock.json modified right after setup

npm on this image rewrites some lockfile metadata. It's harmless. If you want a clean tree, run git restore package-lock.json.

Reset data at any time

The seed script is idempotent. To restore the original workshop data: 

npm run seed
To start completely fresh: 
rm api/finch.db
npm run setup
