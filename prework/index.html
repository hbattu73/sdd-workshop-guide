Prerequisites¶

Complete these steps on your own machine before the first module. The app uses SQLite, an embedded database file, so there is no server or container to set up. Budget about fifteen minutes.

You need four things

  • Node.js 22 or newer and npm
  • git
  • IBM Bob IDE
  • A terminal: Terminal on macOS, PowerShell on Windows, any shell on Linux

1. Install the toolchain¶

These steps assume Homebrew. Don't have it?

If brew --version doesn't return a version, install Homebrew first:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

The installer also sets up Xcode command-line tools, which provide git.

Node.js. 

brew install node
The current formula is Node 26, which is fine; the workshop needs 22 or newer.

git. Already present after the Homebrew install. If git --version prompts you to install command-line tools, accept.

Run everything natively in PowerShell. You do not need WSL for this workshop.

Node.js. Install Node 22 LTS from nodejs.org using the Windows installer. Tick Automatically install the necessary tools: the SQLite driver compiles during setup and needs the Python and C++ build tools that option installs. It adds several minutes to the install.

git. Install Git for Windows. Default options are fine.

Close and reopen PowerShell after installing so the new commands are on your path.

Already working in WSL?

The workshop runs fine inside a WSL distro too. Install Node 22 and git inside the distro, and if npm run setup fails building better-sqlite3, install make (sudo apt install -y make or sudo yum install -y make) and run setup again. To open the repo in Bob from WSL, install the Open Remote - WSL extension in Bob, press Ctrl+Shift+P, choose Connect to WSL, then open the folder from inside that window.

Node.js. Use your distribution's Node 22 package, or nvm: 

nvm install 22

git. sudo apt install -y git or sudo dnf install -y git.

Build tools. The SQLite driver compiles during setup. Most desktop distros already have make, a C++ compiler and Python 3; if npm run setup fails on better-sqlite3, install build-essential (Debian/Ubuntu) or make gcc-c++ python3 (Fedora/RHEL) and run it again.

2. Confirm the toolchain¶

node --version && npm --version && git --version

node --version; npm --version; git --version

You should see Node v22.x or newer and version numbers for npm and git.

3. Clone and set up¶

Terminal
git clone https://github.com/hbattu73/finch-financial.git
cd finch-financial
npm run setup

npm run setup installs dependencies, creates api/.env with working defaults, creates the SQLite database, and seeds it. It takes about a minute. Ignore the npm warn deprecated lines and the vulnerabilities summary at the end; neither affects the workshop.

4. Start the app¶

Terminal
npm run dev

This starts the API (port 3000) and the web app (port 5173) in one terminal. Open http://localhost:5173. Log in with any seeded user; all users share the password Password123!.

You should see a list of customer accounts with status badges, filters by status and name, and an account detail page with transactions, memos and an audit log. If you can browse accounts, the app is ready. Stop it with Ctrl+C.

5. Open the repo in Bob IDE¶

  1. Open IBM Bob.
  2. File → Open Folder and choose the finch-financial folder you cloned.
  3. If Bob asks whether you trust the authors of the folder, click Yes, I trust the authors.

You should see AGENTS.md, product-requests.md and PROMPTS.md in the file tree, and the Bob icon in the activity bar on the left.

Ready

Open the Bob panel and check Settings → Skills: interview is listed with scope Workspace. That's the whole setup.

Testing¶

Both test suites are standalone: no running server and no database setup. Your development data is never touched.

npm test              # everything
npm test -w api       # one workspace
npm test -w web

Troubleshooting¶

npm run setup fails building better-sqlite3

The error block mentions node-gyp rebuild. The SQLite driver is compiled during setup, and the compile needs build tools:

  • macOS: xcode-select --install, then npm run setup again.
  • Windows: rerun the Node installer and tick "Automatically install the necessary tools", or install Visual Studio Build Tools with the C++ workload. Then npm run setup again.
  • Linux: install build-essential (Debian/Ubuntu) or make gcc-c++ python3 (Fedora/RHEL), then npm run setup again.
localhost:5173 doesn't load

Confirm npm run dev is still running. On WSL, if it is and the page still won't load, run hostname -I in the terminal and use that address in place of localhost.

Port 3000 or 5173 is already in use

Another process is holding the port, usually a previous npm run dev.

lsof -ti:3000 | xargs kill
lsof -ti:5173 | xargs kill

Get-NetTCPConnection -LocalPort 3000,5173 -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force -ErrorAction SilentlyContinue }
git status shows package-lock.json modified right after setup

Some npm versions rewrite lockfile metadata. It's harmless. If you want a clean tree, run git restore package-lock.json.

Reset data at any time

The seed script is idempotent. To restore the original workshop data: 

npm run seed
To start completely fresh, stop npm run dev first, then:

rm -f api/finch.db api/finch.db-wal api/finch.db-shm
npm run setup

Remove-Item api/finch.db* -Force -ErrorAction SilentlyContinue; npm run setup
