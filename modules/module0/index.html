Module 0: Get to Know Your Agentic Tool¶

A Wordle Checker Script!¶

wordle_check.py is a small program that scores a Wordle guess against a secret answer (🟩 green / 🟨 yellow / ⬜ gray). Copy and paste it into your IBM Bob editor.

You'll use this file to practice the mechanics of your agent: prompting, mode switching, built-in tools, and wiring up a simple GitHub MCP server.

wordle_check.py
"""
wordle_check.py — score a Wordle guess against the secret answer.

Given a 5-letter guess and the secret answer, return feedback for each
letter position:

    "green"  -> correct letter, correct position
    "yellow" -> letter is in the word, but a different position
    "gray"   -> letter is not in the word

Example:
    >>> score_guess("trace", "slate")
    ['yellow', 'gray', 'green', 'gray', 'green']
"""

WORD_LENGTH = 5

EMOJI = {"green": "\U0001F7E9", "yellow": "\U0001F7E8", "gray": "⬜"}


def score_guess(guess, answer):
    guess = guess.lower()
    answer = answer.lower()

    result = []
    for i in range(WORD_LENGTH):
        g = guess[i]
        if g == answer[i]:
            result.append("green")
        elif g in answer:
            result.append("yellow")
        else:
            result.append("gray")
    return result


def render(guess, answer):
    pattern = score_guess(guess, answer)
    squares = "".join(EMOJI[p] for p in pattern)
    return f"{guess.upper()}  {squares}"


if __name__ == "__main__":
    # A few sample rounds. The answer is SLATE.
    print(render("trace", "slate"))
    print(render("crane", "slate"))
    print(render("eerie", "slate"))

1. Two Kinds of Prompts¶

Ask your agent about the file twice:

  • Lazy: "Does this look correct?"
  • Structured: "Walk through score_guess and check how it handles a guess that repeats a letter the answer only contains once. Give a concrete example."

Notice how differently the two prompts land. Which one surfaces a real problem?

Note

Both prompts should surface the bug, but the structured prompt will give you a far more useful response. The takeaway isn't specific to this file: the more precisely you define what you want the agent to check, the more useful its output will be.

2. Test Out the Modes¶

Bob 2.0 ships with 3 streamlined modes (Ask, Plan, Agent). Move through them in order and notice how the agent's behavior and available tools change at each step:

  • Ask: Map out the file. Have it explain the logic trace and pin down the bug.
  • Plan: Lock the implementation plan. Have it propose a fix (don't let it edit yet).
  • Agent: Implement. Have it apply the fix.

3. Use the Built-in Tools (read + write + run)¶

Now prove the fix holds. Ask your agent to write a few test cases to a new file (including a guess with a repeated letter, e.g. guess EERIE, answer SLATE) and run it. Does the output match what real Wordle would show? Paste back the original version to watch the same test fail; that's the bug you just fixed.

4. Use the GitHub MCP Server (Optional)¶

Setting up the GitHub MCP server for GitHub Enterprise

1. In Bob, go to Settings → MCP, search for GitHub, and click Install. Select your workspace as the installation scope.

2. Generate a PAT at github.ibm.com/settings/tokens/new with at minimum repo scope (or just check all).

3. Set the following:

  • PAT: paste your token from step 2
  • Hostname: https://github.ibm.com
  • Toolsets: repos,issues,pull_requests

4. Open .bob/mcp.json and change "command": "docker" to "command": "podman".

5. Verify the connection (optional)

Run this to confirm the server starts and your PAT is valid: 

echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"0"}}}' | \
  podman run -i --rm \
    -e GITHUB_PERSONAL_ACCESS_TOKEN=<token> \
    -e GITHUB_HOST=https://github.ibm.com \
    ghcr.io/github/github-mcp-server 2>&1 | head -4
You should see both: 
token scopes fetched for filtering   ← auth worked, PAT is valid
GitHub MCP Server running on stdio   ← server started cleanly
Any error on either line tells you exactly what's wrong (bad host format, bad token, network issue) without needing to debug a silent disconnect in Bob.

Your file lives on your machine, but the GitHub MCP can still reach out to GitHub for you:

  • Fetch the reference: pull the README from hbattu/wordle_kata via the GitHub MCP and confirm the correct rule for repeated letters. Compare it to what your agent found in step 1.

  • Stretch goal (if your GitHub token allows): fork hbattu/wordle_kata via the MCP and either file an issue describing the bug or open a PR with your fix. This is a reflection of the real open-source flow, driven entirely through the agent.
